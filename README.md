# Landing Performance Analysis: Manual vs. AI (v0.dev)

Цей репозиторій містить технічний експеримент з A/B тестування двох версій промо-лендінгу. Мета проекту — об'єктивно порівняти якість коду, продуктивність (Web Vitals) та доступність (WCAG 2.2) між традиційною ручною розробкою та генерацією інтерфейсу за допомогою штучного інтелекту (v0.dev).

## Суть експерименту

Розроблено два моксимально ідентичних за дизайном лендінги в архітектурі монорепозиторію (NPM Workspaces):

- **Branch A (Manual):** Написаний вручну, з використанням Tailwind CSS v4.3, оптимізованої HTML5-семантики та кастомних SVG-спрайтів.
- **Branch B (AI v0):** Згенерований за допомогою [v0.dev](https://v0.dev) на базі детального текстового промпта, з використанням Tailwind CSS v4.2 та компонентів shadcn/ui.

Обидві версії розгорнуті в ідентичному серверному середовищі на Vercel.

## Структура проекту

```text
.
├── apps/
│   ├── branch-a-manual/     # Ручна розробка (Tailwind v4.3, оптимізована семантика)
│   └── branch-b-ai/         # Згенеровано v0.dev (Tailwind v4.2, shadcn/ui)
├── scripts/
│   └── experiment-runner.js # Автоматизований Node.js скрипт для аудиту
├── package.json             # NPM Workspaces конфігурація
└── README.md

```

## Технологічний стек

- **Фреймворк:** Next.js 16 (App Router, React 19)
- **Стилізація:** Tailwind CSS, shadcn/ui (для ШІ-версії)
- **Пакетний менеджер:** NPM (Workspaces)
- **Інструменти тестування:** Lighthouse CLI, Axe-core CLI (Deque Systems)
- **Деплой:** Vercel

## Результати аудиту

Для уникнення випадкових відхилень, метрики збиралися автоматизованим скриптом, який проводить серію тестів за допомогою Lighthouse (з троттлінгом мережі та CPU x4) та статичний DOM-аналіз через Axe. Результат та лог чату v0 знаходяться в директорії `results_and_logs`.

| Метрика             | Branch A (Manual) | Branch B (AI v0.dev) | Дельта                      |
| ------------------- | ----------------- | -------------------- | --------------------------- |
| **Performance**     | 100 / 100         | 100 / 100            | 0                           |
| **Accessibility**   | 100 / 100         | 96 / 100             | -4                          |
| **SEO**             | 100 / 100         | 100 / 100            | 0                           |
| **Axe Violations**  | 0                 | 0                    | 0                           |
| **LCP (Швидкість)** | ~1079 ms          | ~1383 ms             | **-304 ms** (Manual швидше) |

### Висновки

1. **Продуктивність:** Сучасні інструменти ШІ-генерації здатні створювати ідеально оптимізований базовий код (Performance 100), який не поступається ручній роботі.
2. **Доступність (A11y):** Ручний код виграє завдяки тотальному контролю над мікро-взаємодіями, контрастністю (`text-slate-400` vs `bg-white`) та `aria`-атрибутами. v0 втратив 4 бали через дрібні порушення семантики.
3. **Швидкість рендерингу (LCP):** Ручна версія виявилася на ~300 мілісекунд швидшою. Це зумовлено легшим CSS-бандлом (відсутність зайвих утилітарних класів) та меншим навантаженням на головний потік під час гідратації клієнтських компонентів.

## Як запустити локально

1. **Встановіть залежності (з кореня проекту):**

```bash
npm install

```

2. **Запустіть ручну версію:**

```bash
cd apps/branch-a-manual
npm run dev

```

3. **Запустіть ШІ-версію:**

```bash
cd apps/branch-b-ai
npm run dev

```

_Лендінги будуть доступні за адресою `http://localhost:3000`._

## Як запустити експеримент (Тестування)

Щоб відтворити автоматизований збір метрик для задеплоєних версій:

1. Переконайтеся, що ви знаходитесь у корені репозиторію.
2. Запустіть бенчмарк:

```bash
npm run test:benchmark

```

3. Скрипт згенерує файл `experiment_results.json` у директорії `scripts/` з детальною агрегацією даних.
